Overview - Module 296: Infrastructure as Code (IaC) Automation

In this module, we will learn and demonstrate:

  • How infrastructure as code replaces manual console work, and how AWS CloudFormation builds repeatable stacks from templates in YAML or JSON (296.1)
  • How a template becomes reusable: parameters, mappings, conditions, intrinsic functions, dynamic references for secrets, outputs, and dependencies (296.1)
  • How nested stacks split a large template, and how StackSets deploy the same stack to many accounts and Regions (296.1)
  • How to change stacks safely: update behaviors, change sets, stack policies, drift detection, rollback, deletion policies, termination protection, and service roles (296.1)
  • How to work faster and still stay in control: template studio, an AI assistant that drafts templates from your requirements, and CloudFormation Git sync (296.1)
  • How AWS X-Ray follows one request across services, with traces, segments, the service map, sampling, instrumentation, security, and cost (296.2)
  • How Git workflows keep CloudFormation files, Terraform files, Python scripts, and architecture documentation under review, with branches, pull requests, automated checks, and deployments from Git (296.3)

1. Workplace Simulation: How It Works

1.1 Modules as Working Group Projects: How It Works

  • Each module in this course is treated as a working group project within our simulated workplace.
  • Working Groups (teams) are expected to collaborate daily, support one another, and manage shared accountability for module success.
  • Every Working Group member has specific responsibilities: complete all assigned quizzes, labs, reflections, and checkpoints (your KPIs), and actively participate in team stand-ups and collaborative work sessions.
  • Working Group Leaders rotate with each new module and serve as the point of coordination, tracking, and reporting.
  • This model aims to simulate a realistic IT team environment, where communication, initiative, and reliability are just as important as technical skills.

1.2 Group Leader Responsibilities

There is one Working Group Leader per group (rotating per module).

  • Initiate daily morning stand-ups.
  • Maintain a shared Stand-up Notes Document (provided).
  • Monitor the group's completion of quizzes, labs, and reflections.
  • Coordinate with the Training Manager (instructor) as needed.
  • Participate in the Working Group leaders' check-in meetings with the Training Manager (instructor).
  • Keep everyone to one minute each (politely cut off if needed).
  • Capture blockers for later discussion (not solved during the stand-up).
  • Ensure the meeting ends on time (10 min hard stop).

1.3 Working Group and Learner Responsibilities

Each Working Group will:

  • Treat each module as a real-world project with clear deliverables and deadlines.
  • Support all Working Group members in completing KPIs, ensuring that no one falls behind.
  • Use daily stand-ups to track progress, identify blockers, and coordinate efforts.
  • Ensure the meeting ends on time (10 min firm stop).

Each learner is responsible for:

  • Submitting and passing all required module assignments, including quizzes, labs, reflections, and checkpoint reviews.
  • Participating in daily Working Group stand-ups and contributing to team collaboration.
  • Asking for help when needed and offering help when able.
  • Tracking their progress and sharing updates with the Working Group.
  • Arriving prepared with yesterday's, today's, and blocker notes.

3. Workplace Scenario Simulation

3.1 The Situation

Scenario

FlashCart Inc. is a fictional online retailer. Its engineers built the first environments by clicking in the console, and now the company has dev, test, and prod accounts, a growing team, and a checkout that is sometimes slow. The CTO wants every environment defined as code, reviewed before it changes, traced end to end, and kept in Git, with no manual steps and no secrets in code.

You are the cloud and DevOps engineer. Over seven phases, the people around you bring real problems. For each one, write your own solution first, then open Show solution to compare.

3.3 Phase 1: Replace Console Clicks With a Template (Lesson 296.1)

Problem

The dev network was built by hand in the console: a VPC, four subnets, an internet gateway, route tables, and a NAT gateway. A week later, production was built the same way, but a route table entry was missing and a security group was wider than in dev. Nobody can say exactly what is in either environment, and a new Region would take days.

Your tasks

  1. Explain why a template is more reliable than console steps or a script of CLI commands.
  2. Name the ways to deploy AWS infrastructure, and say where CloudFormation fits.
  3. Describe what a stack is, and what the work costs.
Show solution
  • Infrastructure as code defines infrastructure in files that a tool turns into resources. The console, the CLI, and the SDK are imperative: you list the steps. A CloudFormation template is declarative: you describe the result, and CloudFormation decides the order, builds in parallel where it can, and manages the resources together.
  • A stack is the group of resources that CloudFormation builds from one template. You create, update, and delete the resources by creating, updating, and deleting the stack, so no ghost resources remain. One template can create many stacks, for example dev, test, and prod, in any Region or account.
  • There is no additional charge for CloudFormation with AWS resource types. You pay for the resources that the stack creates.

3.4 Phase 2: One Template for Dev and Prod (Lesson 296.1)

Problem

FlashCart wants one template for both environments: a small server and no extra tag in dev, a larger server and a Critical tag in prod. The orders database needs a master password that must not appear in the template, in Git, or in stack events. A subnet name must include the stack name and the Region, and the app servers must not count as created until their software is installed. The first deployment of a template with a named IAM role fails with an InsufficientCapabilities error.

Your tasks

  1. Choose a parameter, a mapping, and a condition for the dev and prod differences.
  2. Keep the password out of the template, and explain what NoEcho does not hide.
  3. Wait for the instances, and fix the capabilities error.
Show solution
  • An Environment parameter selects dev or prod, a mapping looks up the instance type, and a condition such as Fn::If with AWS::NoValue adds the Critical tag only in prod.
  • Use a dynamic reference to AWS Secrets Manager or Systems Manager Parameter Store. NoEcho masks a parameter in stack descriptions and events, but it does not mask the Metadata section, the Outputs section, or a resource’s Metadata attribute.
  • Fn::Sub with the AWS::StackName and AWS::Region pseudo parameters builds the name. A CreationPolicy with cfn-signal makes CloudFormation wait for the instances, and a missing signal before the timeout rolls the stack back.
  • A role with a custom name needs the CAPABILITY_NAMED_IAM capability. CAPABILITY_IAM covers IAM resources without custom names, and CAPABILITY_AUTO_EXPAND covers macros.

3.5 Phase 3: Scale With Nested Stacks and StackSets (Lesson 296.1)

Problem

The production template now has more than 400 resources, and three teams edit it. FlashCart also has separate accounts for dev, test, and prod, and Security wants the same IAM roles and AWS Config rules in every account and Region, including accounts that join later. The network stack must also share its subnet ID with the application stack.

Your tasks

  1. Split the large template into reusable parts.
  2. Deploy one baseline to many accounts and Regions, including new accounts.
  3. Share a value between two stacks, and name the restrictions.
Show solution
  • Nested stacks split a template into modules that a parent stack creates and manages in one account and Region. One operation cannot create, update, or delete more than 2,500 resources in a nested hierarchy, and a change set with IncludeNestedStacks previews the whole hierarchy.
  • StackSets deploy the same template to many accounts and Regions. Service-managed permissions with automatic deployment add the stack to accounts that join the target organizational units later. Operation preferences set how many accounts run at once and how many failures are tolerated.
  • A cross-stack reference exports an output and imports it with Fn::ImportValue. It works only in the same account and Region, the export name must be unique in the Region, and you cannot delete the exporting stack or change the exported value while another stack imports it.

3.6 Phase 4: Change Production Safely (Lesson 296.1)

Problem

Before a change to the production database template, the architects want to see what will be replaced. They also want to stop anyone from replacing the orders database by accident. An engineer opened a security group in the console and never closed it, so the live stack no longer matches the template. A rollback failed after someone deleted a database outside CloudFormation, a test stack deletion must keep its data, and engineers should not need broad permissions to create stacks.

Your tasks

  1. Preview an update, and predict whether a resource is modified or replaced.
  2. Block replacement of the database, and find the manual change.
  3. Recover from the failed rollback, protect the data, and give limited permissions.
Show solution
  • A change set previews which resources are added, modified, replaced, or deleted, and applies nothing until you execute it. Replacement creates a new resource with a new physical ID, and a database that is replaced starts empty.
  • A stack policy that denies Update:Replace and Update:Delete on the database blocks the update for everyone. Drift detection reports a resource as IN_SYNC, MODIFIED, DELETED, or NOT_CHECKED, and the stack as DRIFTED, but it repairs nothing.
  • A stack in UPDATE_ROLLBACK_FAILED needs ContinueUpdateRollback, with the minimum resources skipped. DeletionPolicy Retain or Snapshot, and UpdateReplacePolicy, protect data, and termination protection stops a stack from being deleted.
  • A CloudFormation service role lets people create stacks with only the permission to use CloudFormation and to pass the role (iam:PassRole). Other users of the stack can use the role without iam:PassRole, so keep it least privilege.

3.7 Phase 5: Build Faster With Template Studio, AI, and Git Sync (Lesson 296.1)

Problem

A new engineer cannot picture ten resources in three hundred lines of JSON. Engineers have started to ask AI assistants for templates, and one draft opened SSH to the whole internet, while another named an S3 bucket in a way that S3 rejects. The team also does not want to build another pipeline only to update CloudFormation stacks.

Your tasks

  1. Read the template and a diagram of its resources side by side.
  2. Use an assistant, and check its draft before you deploy it.
  3. Update a stack from a Git repository, and say what Git sync does not do.
Show solution
  • Template studio in the CloudFormation console shows the template text beside a diagram of its resources in the Both view. You edit the text, and the diagram redraws. Connections come from Ref, Fn::GetAtt, Fn::Sub, and DependsOn.
  • Use the requirements-first method: write the requirements, prompt with context, task, requirements, constraints, and output format, then review. Check the syntax, the resource types, the intrinsic functions (every Fn::Sub variable needs ${ }), the security rules, the names and limits, the order, the deletion behavior, and the cost. Never paste secrets into a prompt.
  • CloudFormation Git sync monitors a template file and a stack deployment file in one branch of a repository, and updates the stack when you commit a change. It deploys, but it does not run your own checks such as cfn-lint. It is not part of the exam scope, but it is part of day-to-day work.

3.8 Phase 6: Trace Slow Checkouts With AWS X-Ray (Lesson 296.2)

Problem

Checkout takes eight seconds for some customers and two for others. A request goes through the web front end, the order service, the payment service, a database, and an email service, and each team says that its part is fast. FlashCart also worries that tracing every request would be expensive, and a developer reads that the X-Ray SDK and daemon are in maintenance mode.

Your tasks

  1. Choose the service that finds the slow step in the request path.
  2. Turn on tracing for Lambda and API Gateway, and control the cost.
  3. Find the gold-tier requests that took longer than five seconds, and answer the SDK question.
Show solution
  • AWS X-Ray follows one request across services. A trace holds the segments of the request, and subsegments record downstream calls. The service map shows the latency and the errors of each node.
  • Set the Lambda tracing mode to Active and allow xray:PutTraceSegments and xray:PutTelemetryRecords. Turn on tracing for the API Gateway stage. Sampling controls the cost: by default, X-Ray traces the first request each second and five percent of the rest.
  • Record the customer tier as an annotation, which is indexed, and use a filter expression or a group. Metadata is not searchable.
  • The SDKs and the daemon entered maintenance mode on February 25, 2026, with end of support on February 25, 2027, and AWS recommends OpenTelemetry. Define the tracing settings in CloudFormation so that every environment is traced the same way.

3.9 Phase 7: Put Everything in Git (Lesson 296.3)

Problem

The templates live on laptops. A contractor pushed a Python script that contained an AWS access key to a public repository, and another engineer committed a Terraform state file. Two engineers ran terraform apply at the same time. The architecture diagram in the wiki shows a database that was removed months ago.

Your tasks

  1. Set up a workflow in which every change is reviewed.
  2. Deal with the leaked key and the state file.
  3. Keep the documents accurate, and run checks automatically.
Show solution
  • Use the GitHub flow: a branch, small commits, a pull request, review and checks, a merge, a deployment, and branch deletion. Protect main with required reviews and required status checks, and undo a change with git revert.
  • Deactivate the key in IAM at once, because deleting the commit does not remove copies. Use git-secrets and secret scanning with push protection. Never commit state. Store Terraform state in an S3 backend with locking, and commit .terraform.lock.hcl.
  • Keep the architecture documents in the same repository and change them in the same pull request. Record decisions as ADRs. Run cfn-lint, terraform fmt, validate, and plan, and a secret scan on every pull request, and give the pipeline AWS access with OIDC and an IAM role instead of stored keys.

4. Debrief Questions

Answer each question in your own words first, then expand the model answer to compare.

  1. Why do infrastructure files belong in code, and how does a declarative template differ from a script of CLI commands?

    Show model answer

    A template is text, so it can be stored, reviewed, repeated, and restored. A CLI or SDK script is imperative: you list the steps, their order, and the error handling. A CloudFormation template is declarative: you describe the result, and CloudFormation decides the order, builds in parallel where it can, and manages the resources together as a stack.

  2. What is a stack, and how does it differ from a template?

    Show model answer

    A template is the blueprint, a JSON or YAML file that describes resources. A stack is the group of real resources that CloudFormation builds from it, in one account and one Region. You create, update, and delete the resources by creating, updating, and deleting the stack, and one template can create many stacks, for example dev, test, and prod.

  3. How do parameters, mappings, and conditions differ, and how do you keep a database password out of a template?

    Show model answer

    A parameter takes an input when you create or update the stack, a mapping is a fixed lookup table that Fn::FindInMap reads, and a condition decides whether a resource is created or a property gets a value. For a password, use a dynamic reference to Secrets Manager or Parameter Store. NoEcho does not hide values in the Metadata or Outputs sections.

  4. How do nested stacks, cross-stack references, and StackSets differ?

    Show model answer

    Nested stacks are child stacks that a parent creates and manages in one account and Region, and they help with size and reuse. Cross-stack references share an exported output with another stack in the same account and Region, and they block deleting the exporting stack while it is imported. StackSets deploy the same stack to many accounts and Regions, with automatic deployment for new accounts under service-managed permissions.

  5. How do a change set, a stack policy, and drift detection differ?

    Show model answer

    A change set previews an update and applies nothing until you execute it. A stack policy is a JSON document that blocks the update actions that you deny, for everyone who updates the stack. Drift detection compares the real resources with the template and reports resources as IN_SYNC, MODIFIED, DELETED, or NOT_CHECKED, and the stack as DRIFTED, but it repairs nothing.

  6. How do DeletionPolicy, termination protection, and a service role protect data and permissions?

    Show model answer

    DeletionPolicy and UpdateReplacePolicy with Retain or Snapshot keep or back up a resource when a stack deletes it or an update replaces it. Termination protection stops a stack from being deleted. A service role gives CloudFormation its own permissions, so people need only the permission to use CloudFormation and iam:PassRole for the role, and the role must stay least privilege because other users of the stack can use it.

  7. What do template studio and an AI assistant each add, and how do you check an AI draft?

    Show model answer

    Template studio shows the template text beside a diagram of its resources, and the diagram redraws as you edit the text. An AI assistant drafts a template from your requirements. Review the draft before you deploy it: check the syntax, the resource types and properties, the intrinsic functions, the security rules, the names and limits, the order of creation, the deletion behavior, and the cost, and never paste secrets into a prompt.

  8. What does CloudFormation Git sync do, and what does it not do?

    Show model answer

    Git sync monitors a template file and a stack deployment file in one branch of a repository and updates the stack when you commit a change. It removes the need for a deployment pipeline just to update stacks. It does not run your own checks, such as cfn-lint or a secret scan, and it covers CloudFormation only. It is not on the exam, but it is useful at work.

  9. How do a trace, a segment, and a subsegment relate, and how do you turn on tracing for Lambda?

    Show model answer

    A trace holds all the segments that one request generated. A segment records the work of one service, and a subsegment records a downstream call or a block of code. For Lambda, set the tracing mode to Active and allow xray:PutTraceSegments and xray:PutTelemetryRecords on the execution role, for example with the AWSXRayDaemonWriteAccess managed policy.

  10. How does X-Ray sampling control cost, and what happened to the X-Ray SDK and daemon?

    Show model answer

    By default, X-Ray traces the first request each second and five percent of the additional requests, and you can add rules that trace every request only for important paths. The SDKs and the daemon entered maintenance mode on February 25, 2026, with end of support on February 25, 2027, and AWS recommends OpenTelemetry.

  11. How does the GitHub flow protect the main branch, and what do you do when an access key is committed?

    Show model answer

    You work on a branch and open a pull request. The main branch is protected with required reviews and required status checks, and nobody pushes to it directly. If an access key is committed, deactivate it in IAM at once, because deleting the commit does not remove other copies, and use git-secrets and secret scanning so that it does not happen again.

  12. How do you store Terraform state safely in a team, and how does a pipeline get AWS access without stored keys?

    Show model answer

    Never commit state, which can hold sensitive values and cannot be locked by Git. Store it in an S3 backend with encryption, versioning, and locking, and commit the .terraform.lock.hcl file. With OpenID Connect, a workflow gets a short-lived token for each run and exchanges it for temporary AWS credentials by assuming an IAM role, so no access key is stored.
